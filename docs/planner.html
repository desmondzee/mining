Haul Path Planner

The planner takes the map around one truck and the truck state. It returns 16 waypoints for the next 8 seconds. A* solves this today (Plan A). A small network learns to copy A* (Plan B). This page runs A* live, so you can see the input and output.

The LLM dispatcher sits above the planner. It picks the goal (which pit or dump) for each truck. The risk monitor reads the front radar distance and the truck speed, and it warns before the point of no return.

What the model sees and returns

A 128 m × 128 m window around the truck, rotated so that the truck faces up. The truck sits 32 m from the bottom edge. Cells are 2 m, so each channel is 64 × 64.

Input / output contract (proposal)

The planner team owns this contract. Unity, the CV teammate and the risk monitor read and write these fields. All positions are in metres, in the truck frame: +x forward, +y left.

Two plans

Plan A · no training · demo fallback

A* + smoothing + path follower

  1. Build the cost grid from road, slope and obstacles.
  2. Run A* from the truck to the goal.
  3. Smooth the path and check the 15 m turning radius.
  4. Send 16 waypoints to Unity. Unity follows them.
  5. Plan again when CV reports a new obstacle.

Grid A* gives sharp 45° steps. Smoothing removes most of them. Hybrid A* (A* that plans with the turning radius) removes all of them, but it costs more time.

Plan B · imitation of A* · 1–5M parameters

Small CNN that copies A*

  1. Generate 1,000 maps with random start and goal on the Cambridge machine.
  2. Run A* on each map. Cut each path into samples, one every 0.5 s: about 50 per path, about 50,000 samples in total.
  3. Train the CNN: BEV + state in, A* waypoints out. Loss = mean distance error. About 10 min on one 3090.
  4. Export to ONNX. Run with Core ML on the M5, or TensorRT on the GB10.
  5. Show the model path and the A* path together in the demo.

Online RL (Unity ML-Agents, PPO) can tune the model later. It needs millions of steps, so it is not in scope before 15:30.
