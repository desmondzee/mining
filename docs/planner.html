Haul Path Planner

Each truck gets a route from the road graph. A learned driving policy follows that route and steers around moving vehicles, ten times per second, as FSD does. A* with a rule-based local planner is the baseline that the model must beat. The map below is the real default world from vato/environment.

Terms on this page

LidarA laser scanner. It sends light pulses and measures the time to return, so it gives many precise 3D points. Our Unity truck has one: 120° wide, 100 m range, 10 scans per second.
RadarUses radio waves. Fewer points and less exact shape, but it measures speed directly and sees through dust and rain. Real mine trucks often use both. Our sim has lidar only.
ThrottleThe accelerator pedal: 0 = no power, 1 = full power.
SteerThe steering wheel: −1 = full left, 0 = straight, +1 = full right (30° at the wheels).
MetresAll distances on this page are sim metres from the world files. Unity uses the same units, so the numbers carry over. Nothing here is measured on a real site.

Three input/output designs

All three take the same input. They differ in what the model returns. The website needs a path to draw, and the truck needs throttle and steer, so every design must give both in the end.

Design 1 · direct control

Output: throttle + steer

2 numbers, sent straight to the truck. This fits brain as it is now and is natural for RL. There is no path to show: we must simulate one forward for the website. Hard to check for safety before acting.

Design 2 · path ("wayfinding")

Output: 16 waypoints

The next 8 s of path, one point every 0.5 s. A small path follower turns it into throttle + steer. Easy to show and to check. This is what Desmond asked for. Easy for imitation learning, harder for RL.

Design 3 · recommended · pick a path

Output: a score for each of 44 candidate paths

The sim makes 44 drivable 3 s paths (the grey lines). The model scores them, and the truck drives the best one. We get a path to show and throttle + steer. Unsafe paths are removed before the model scores them. Works for imitation (copy the baseline's pick) and for RL (44 discrete choices).

Data and training plan

Data
  1. Map: the real nav grid of each world (navgrid.json).
  2. Scenarios: random start and goal sites, 2–6 moving vehicles on the roads, random speeds and load.
  3. For A: run the baseline on 2,000 scenarios, about 600 ticks each, and save (input, chosen path).
  4. For B: no saved data. 64 copies of the 2D sim run at the same time and make data while the model trains.
Machines
  1. 3090 #1: Training A, then Training B.
  2. 3090 #2: a second Training B run with other reward weights.
  3. Modal credits: data generation in parallel, and a backup if Cambridge SSH drops.

Task assignment (the orchestrator)

The LLM understands the operator, and code does the scheduling. An LLM is good at reading "the north pit is flooding, move everyone to the east bench". It is not good at timing 4 trucks against 2 excavators.

1 · LLM

Words to tool calls

Uses the tools in CONTRACT.md: assign_haul, go_to, hold, resume, avoid_site, status_report. Replies over the radio.

2 · Scheduler

Who goes where

For each free truck, score each ore site: travel time + queue at the loader − tonnes left. Pick the lowest. Plan again when a truck finishes, a site runs out, or a road closes.

3 · Truck state machine

to_load → loading → hauling → dumping → returning

Already named in the contract. Each state sets the goal for the driving policy. The risk monitor can move any truck to holding.

The CV teammate and RefAV

RefAV (CVPR 2026) does not detect obstacles. It is scenario mining: you ask in plain words, for example "a light vehicle crosses in front of a loaded haul truck", and an LLM writes a short program over tracked objects that finds where and when this happens in driving logs. It needs a detector and tracker first.

How it fits us: (1) the CV teammate still needs a detector for live obstacles; (2) RefAV-style mining over our sim logs finds near misses and hard cases, which become extra training scenarios and test cases for the comparison table above.
