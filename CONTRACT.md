# Integration contract

Every workstream builds against this file. If you need to change it, keep changes additive (new optional fields) and note them at the bottom under "Changes".

Demo: autonomous open-pit mine. Operator speaks over "radio" → speech-to-text → LLM dispatcher → haul trucks re-tasked → trucks drive via A* on a nav grid and reply with TTS voices. The environment is generated by World Labs Marble (with a procedural fallback). Clicking a truck shows a Reactor LingBot World 2 live "driver's-eye" stream steered by that truck's drive intent.

## Repo layout
```
envgen/   Python: world generation (procedural fallback + World Labs Marble pipeline) → data/worlds/<id>/
server/   Python 3.12 FastAPI, entry `app.main:app`, port 8000. Sim, fleet, A*, dispatcher, voice, Reactor token.
web/      Vite + React + TypeScript + @react-three/fiber. Built to web/dist, served by nginx.
unity/    Unity 6 editor importer + runtime WebSocket client (optional renderer).
deploy/   docker-compose.yml, Dockerfiles, nginx.conf, Caddyfile, .env.example
data/worlds/<world_id>/   generated worlds (mounted into server container at /app/data)
```

## Coordinates and units
Metres. Right-handed, **Y up**, X east, Z north (Three.js convention; Unity importer flips Z if needed). Ground positions in JSON are `[x, z]`; 3D positions are `[x, y, z]`.

## World directory: `data/worlds/<world_id>/`
- `world.json` (required)
- `navgrid.json` (required)
- optional: `splat_500k.spz`, `splat_100k.spz`, `collider.glb`, `pano.jpg`, `concept.png`, `terrain.glb`, `heightmap.raw` (Unity 16-bit LE, square 2^n+1)

A world with id `default` must always exist (procedural, generated without any API keys).

### world.json
```json
{
  "id": "default",
  "name": "Copper Ridge Pit",
  "source": "procedural",            // "procedural" | "marble"
  "size_m": [400, 400],               // extent in x, z
  "origin": [-200, -200],             // min corner [x, z]
  "assets": {
    "splat": null,                    // "splat_500k.spz" when source = marble
    "collider": null,                 // "collider.glb"
    "terrain_mesh": "terrain.glb",    // mesh for renderers without splats (procedural always provides it)
    "pano": null,
    "concept": null,
    "heightmap_raw": "heightmap.raw"
  },
  "splat_transform": { "scale": 1.0, "ground_offset": 0.0, "rotation_euler_deg": [0, 0, 180] },
  "sites": [
    { "id": "crusher",    "type": "crusher", "name": "Primary Crusher", "pos": [120, 40] },
    { "id": "dump_west",  "type": "dump",    "name": "West Waste Dump", "pos": [-150, 60] },
    { "id": "pit_north",  "type": "ore",     "name": "North Bench",     "pos": [10, 90],  "tonnes": 6000 },
    { "id": "pit_east",   "type": "ore",     "name": "East Bench",      "pos": [70, -20], "tonnes": 4000 },
    { "id": "parking",    "type": "parking", "name": "Ready Line",      "pos": [150, -120] },
    { "id": "fuel",       "type": "fuel",    "name": "Fuel Bay",        "pos": [170, -90] }
  ],
  "trucks": [
    { "id": "T1", "callsign": "Truck 1", "spawn": [150, -110], "heading_deg": 0, "capacity_t": 200 }
  ],
  "navgrid": "navgrid.json"
}
```
Site types: `crusher | dump | ore | parking | fuel`. Ore sites deplete. 4–6 trucks.

### navgrid.json
```json
{
  "width": 200, "height": 200,        // cells in x, z
  "cell_m": 2.0,
  "origin": [-200, -200],             // world [x, z] of cell (0,0)'s min corner
  "heights": [ ... ],                 // float metres, row-major, index = row * width + col, row = z index
  "cost":    [ ... ]                  // float, 1.0 = flat road; >1 harder; -1 = impassable
}
```

## Server HTTP API (port 8000)
- `GET  /api/health` → `{"ok": true}`
- `GET  /api/worlds` → `[{"id","name","source"}]`
- `GET  /api/world` → current world.json plus `"base_url": "/worlds/<id>/"`
- `POST /api/world/load` `{"world_id"}` → loads world, respawns trucks
- `GET  /worlds/<id>/<file>` → static files from data/worlds
- `POST /api/command` `{"text"}` → `{"tool_calls":[{"name","args"}], "replies":[{"truck_id","callsign","text","audio_url"}]}`
- `POST /api/stt` multipart field `audio` (webm/ogg/wav) → `{"text"}`
- `GET  /api/audio/<id>.mp3` → generated TTS audio
- `POST /api/reactor/token` → `{"jwt"}` (server exchanges REACTOR_API_KEY at `POST https://api.reactor.inc/tokens`; key never reaches the browser)
- `POST /api/sim/reset`, `POST /api/sim/speed` `{"multiplier"}`

## WebSocket `GET /ws` (server → client JSON messages, ~10 Hz)
```json
{"type":"state","t":12.3,
 "trucks":[{"id":"T1","callsign":"Truck 1","pos":[x,y,z],"heading_deg":90,"speed_mps":8.2,
            "state":"idle|to_load|loading|hauling|dumping|returning|holding|to_site",
            "load_t":0,"capacity_t":200,"task":"Haul North Bench → Crusher",
            "path":[[x,z],...],                   // remaining planned path
            "ghost_paths":[[[x,z],...],...],      // candidate routes the planner "imagined" (shown as faint lines)
            "drive":{"longitudinal":"forward|idle","lateral":"left|right|none","yaw_rate_dps":0}}],
 "sites":[{"id":"pit_north","tonnes":5400}]}
{"type":"radio","from":"Dispatch"|"Truck 3","truck_id":"T3"|null,"text":"...","audio_url":"/api/audio/abc.mp3"|null,"t":12.3}
{"type":"event","kind":"world_loaded|task_assigned|load_complete|site_depleted","data":{...}}
```
Client → server over WS (optional): `{"type":"command","text":"..."}` (same as POST /api/command).

## Dispatcher tools (LLM function calling)
- `assign_haul(truck_ids: string[] | ["all"], source_site: string, dest_site: string, loads?: int)`, repeats load→haul→dump until loads done or source depleted
- `go_to(truck_ids, site)`
- `hold(truck_ids)` / `resume(truck_ids)`
- `avoid_site(site, reason)`: mark area around a site impassable (e.g. "north pit flooding")
- `status_report(truck_ids)`: trucks reply with state over radio
Each affected truck answers with a short radio-style acknowledgement ("Copy dispatch, Truck 3 hauling North Bench to crusher.").

## Environment variables (deploy/.env)
```
OPENAI_API_KEY=
OPENAI_BASE_URL=            # optional, OpenAI-compatible gateway (e.g. Vercel AI Gateway)
OPENAI_MODEL=gpt-4.1-mini
ELEVENLABS_API_KEY=
ELEVENLABS_VOICE_IDS=       # comma-separated, one per truck; dispatch uses the first
REACTOR_API_KEY=
WLT_API_KEY=                # World Labs
DATA_DIR=/app/data
```
Everything must degrade gracefully when a key is missing: no OpenAI key → regex/keyword fallback parser; no ElevenLabs key → `audio_url: null` (browser may use speechSynthesis) and the browser can type commands; no Reactor key → panel shows "stream unavailable".

## Docker
- `server`: python:3.12-slim, port 8000, volume `../data:/app/data`
- `web`: node build stage → nginx:alpine; nginx serves dist and proxies `/api`, `/ws` (upgrade), `/worlds` to `server:8000`

## Changes

- **envgen (additive):**
  - `world.json.assets` may also carry `preview` (`preview.png`), `heightmap_meta` (`heightmap_meta.json`), `splat_lowres` (`splat_100k.spz`) and `thumbnail`. Optional top-level blocks: `generator` (procedural params) and `marble` (`world_id`, `marble_url`, `caption`, `model`).
  - `heightmap_meta.json` holds `resolution`, `size_m`, `origin`, `min_height_m`, `max_height_m` and `height_range_m`. Read the raw file as `world_y = min + v/65535*range`. Row 0 is the south edge (min z) and column 0 is west (min x).
  - `splat_transform` for Marble: `{scale, ground_offset, rotation_euler_deg: [180,0,0], frame: "opencv", order}`. Apply `p = raw*scale`, then `p.y -= ground_offset` in the raw OpenCV frame, then rotate 180° about X. Marble assets are OpenCV (+y down), so the rotation negates y and z. The example's `[0,0,180]` is not what envgen writes. Procedural worlds use `[0,0,0]` and scale 1.
  - For Marble worlds, `navgrid.cell_m`, `width`/`height` and `origin` follow the collider extent (cell ≈ extent/220 m, at least 0.5 m). Consumers must read them, not assume 2.0 / 200x200 / -200.
  - Site ids differ per world; consumers should look sites up by `type`.
    - `default`: `crusher`, `dump_south`, `parking`, `fuel`, `pit_floor`, `pit_west`, `pit_east`.
    - Marble: `ore_1..3`, `crusher`, `dump`, `parking`, `fuel`.
  - envgen writes to `$DATA_DIR/worlds/<id>/`, defaulting to `./data/worlds`.

### Roads and labels (added for Unity / nav handoff)
world.json gains (all metres, Y up, points are 3D `[x, y, z]` with y = terrain height + 0.0):
```json
"junctions": [ { "id": "j_ramp_top", "name": "Ramp Top", "pos": [100.6, -0.2, 48.9] } ],
"roads": [
  { "id": "ramp_main", "name": "Main Haul Ramp", "type": "ramp",      // ramp | haul | spur
    "from": "j_ramp_top", "to": "pit_floor",                            // site or junction ids
    "width_m": 14, "grade_pct": 9.0, "one_way": false,
    "points": [[100.6, -0.2, 48.9], ...] }                              // centreline, ~5 m spacing, ordered from -> to
]
```
Every site gets `"pos3": [x, y, z]` (terrain height at its pos) and keeps `name` as its display label.
Roads + junctions form a connected graph: every site is the endpoint of at least one road.
Unity mapping: contract (x, y, z) -> Unity Vector3(x, y, z) directly.

### Design spec, bounds, trucks (envgen, additive)
- `world.json` gains `"bounds": [xmin, zmin, xmax, zmax]`, which equals the world extent. The procedural default is now a 260 m lease, so `[-130,-130,130,130]` with `origin [-130,-130]` and navgrid 130x130 @ 2 m. Read `size_m`/`origin`/`bounds`; do not assume 400 m.
- `world.json` gains `"design"`. It holds the pit/haul-road design spec, all metres/degrees/percent: `design_truck` {name, payload_t, width_m, length_m, tire, tire_diameter_m, turning/clearance diameters ...}, `bench_height_m`, `n_benches`, `face_angle_deg`, `berm_width_m`, `inter_ramp_angle_deg`, `overall_slope_deg`, `ramp_grade_pct`, `road_width_m`, `ramp_width_m`, `safety_berm_height_m`, `cross_fall_pct`, `min_curve_radius_m`, `floor_radius_m`, `checks` / `violations` / `warnings`, `references`, `notes`, and `as_built` (geometry measured back from heightmap.raw). See `envgen/DESIGN_SPEC.md`.
- `roads[].width_m` equals `design.ramp_width_m` for `type: "ramp"` and `design.road_width_m` otherwise. The default design truck is the Komatsu HD465-7, so these are 16.5 m and 15 m.
- The procedural default now has **3 trucks with ids `truck-0`, `truck-1`, `truck-2`** (callsigns "Truck 0..2"), replacing T1..T5. Each has `capacity_t` = design-truck payload (55) plus an optional `model` string.
- `trucks[].heading_deg` convention: 0 = +z (north), clockwise positive when viewed from above (Unity `eulerAngles.y`), i.e. `heading = atan2(dx, dz)`.
- The default site ids are unchanged except the bench ore sites, which are now `pit_south` and `pit_west`. Their ids derive from compass direction, so look sites up by `type`.
- `procedural.py --truck komatsu_hd465|cat785d|cat797f|komatsu930e`. The big-truck presets auto-size the world (500–600 m, heightmap 1025 when > 500 m).
